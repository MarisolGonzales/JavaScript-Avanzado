Recorrido de una compra

La funcionalidad principal atraviesa todas las capas.

Ver el juego

JuegoDetalle lee el id con useParams y los datos con useQuery.

Añadir al carrito

dispatch({type:'agregar'}) en el useReducer del CarritoContext; un useEffect lo guarda y lo sincroniza.

Pagar

<form action={pagar}> con useActionState valida (Luhn, RUC, DNI); useFormStatus muestra «Procesando pago…».

Enviar a la API

pedidosApi.crear → Axios añade el token → Express descuenta stock → Zod valida la respuesta.

Actualizar la caché

invalidateQueries de pedidos, biblioteca y juegos; se vacía el carrito y navigate lleva al pedido.

Ver el pedido

use(promesa) dentro de Suspense y ErrorBoundary; el PDF se descarga con Axios como blob.

Relación con los laboratorios

Laboratorio 13 · Hooks

Agenda → useReducer del carrito. Catálogo → useDeferredValue, useTransition, memo. Foco → CampoTexto. Plataforma → useConexion. Reserva → useActionState, useFormStatus, useOptimistic. Recursos → use + Suspense + ErrorBoundary. Avisos → useEffectEvent.

Laboratorio 14 · Servicios

Axios con interceptores, TanStack Query (useQuery, useMutation, invalidación), contrato con Zod, cancelación con AbortSignal y proxy /api en Vite.

Laboratorio 10 · Angular

La versión anterior del frontend sigue en nexus-gaming-frontend/. La versión React usa su mismo SCSS y el mismo HTML en cada pantalla, y reutiliza su lógica pura (dinero, Luhn, RUC, índice de búsqueda, burbuja, QR, instalación) en src/logic/.

Pruebas

13 pruebas con Vitest y Testing Library: reductor del carrito, validaciones del pago, reglas de estado, carrusel del inicio, GameCard, CampoTexto, ErrorBoundary, useConexion y el catálogo con TanStack Query.
